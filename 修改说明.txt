P58 修订：护肤品库存改成「只数未开封的整瓶」

原来的写法把两件事混在一个数字里：既像是「一共几瓶（含正在用的）」，
又像是「囤了几瓶」，还给未填留了一个「—」的中间状态，卡片上又重复标「未开封」。
现在统一成一个口径：

1. 库存 = 还没拆封的整瓶数，永远是一个整数，默认 0。
   正在用的那一瓶不计入；不再有「—」「未记库存」这种半记录状态。

2. 卡片只讲一次状态，不再重复：
   - 已开封：🧴 使用中 · 11-01 开封 · 剩 N 天，下一行「📦 另有未开封 2 瓶」。
   - 未开封：剩 N 天 / 到期，下一行「📦 未开封 3 瓶」。
   0 瓶时不再标红「已用完」，改成「瓶 · 没有囤货」「瓶 · 点 ＋ 记上」。

3. 开封自动扣一瓶：
   「✓ 今天开封了」= 从囤货里拿走一瓶 → 未开封 -1，重新开始倒计时；
   已开封的产品如果还有囤货，卡上会出现「✓ 这瓶用完了，开下一瓶」，同样扣 1 并重新计时。
   「－」的含义也写清楚了：少记一瓶（送人 / 记错了），不是「用掉一瓶」。

4. 添加表单：字段名改为「未开封囤货 · 瓶」，留空 = 0，不再默认 1。

5. 旧数据自动迁移（只跑一次，标记位 app_h_prodStockV2）：
   - 已开封且库存是 1 的 → 归 0（旧版留空默认 1 的假数据，真有一瓶备用可在卡片上点 ＋ 补回）；
   - 未开封且库存 1 → 保留（那一瓶本身就是囤货）；
   - 空值 / null → 0。

自查：jsdom 新增 21 项库存专项断言（留空=0、囤 3 瓶、开封扣 1、开下一瓶、± 不为负、
旧数据迁移、单卡「未开封」只出现一次）全过；原 47 项回归全过；ci/verify.py 20 项全过。

P59 修订：200 秒走动倒计时「回前台接续」+「到点只响一次」

1. 到点不再响两遍
   以前原生服务 onFinish 播一次「时间到，请站起来活动一下」，
   同一时刻页面 tick 走到 0 又播一次「时间到，回到座位继续吧」，语音/震动/提示音叠在一起。
   现在由「谁计时谁播报」决定：
   - JS 调 startNativeWalkTimer() 会拿到返回值，true = 原生接管；
   - 原生接管时，页面到点只收起弹层，不播报、也不 stopService（避免掐断原生那句语音）；
   - 原生没接管（后台启动被拒 / 服务没起来）时，才由页面补播一次，并顺手停掉服务与结束闹钟。

2. 后台被闹钟叫醒后，回前台能接上剩余时间
   以前后台弹提醒时页面不起倒计时（有意为之），回到前台就看不到剩余秒数，只能看通知栏。
   现在 WalkTimerService 记录结束时刻 sEndTs，JsBridge 新增 getWalkRemainingSec()；
   页面回前台若发现原生还在跑，就把剩余秒数接过来继续显示（静默模式：不重播「该站起来走动了」、不重复起服务）。

3. 顺带修好的小问题
   - 回前台时若弹层还挂着但早就过点，静默收起，不再补播一次「时间到」；
   - 用户点「关闭 / 知道了」时静默收尾并停服务，不播报。
